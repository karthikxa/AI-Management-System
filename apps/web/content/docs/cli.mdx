The `zed` command line interface (CLI) controls Zed from a terminal — your laptop or a session sandbox. This page shows the everyday dev loop, then lists every stable command and flag.

## Install

```sh
curl -fsSL https://zed.com/install | bash
```

The installer downloads a prebuilt binary for macOS and Linux. Windows is not supported.

| Command | Effect |
| --- | --- |
| `zed update` | Re-run the install script and pull the latest binary. |
| `zed uninstall [-y\|--yes] [--keep-auth] [--keep-home]` | Remove the binary, the `/usr/local/bin` shim, and the stored token. `--keep-auth` keeps the token. `--keep-home` keeps `~/.zed`. |
| `zed version` | Print the CLI version. |

## Auth model

Zed stores authentication per host, not globally. A host is one Zed API endpoint. Four hosts exist by default: `cloud` (Zed Cloud), `selfhost` (your self-hosted stack), `local-dev`, and `zed-internal-dev`. You can add more.

The config file lives at `~/.config/zed/config.json`, mode `0600`. Override its path with `ZED_CONFIG_FILE`.

The CLI follows one hierarchy: host → account → project → session. You sign in to a host, pick an account inside it, pick a project inside that account, and open sessions inside the project. `zed hosts login` walks the first three steps in order: it signs you in, picks the account, then sets a default project.

Every token starts with `zed_pat_`. A user token, from `zed login`, sees every account and project you belong to. A project token is auto-minted for a session sandbox and scoped to one project. See [Token scope](#token-scope).

## The dev loop

This loop assumes the CLI is installed and you ran `zed login`. See [Quickstart](/docs/quickstart) for setup.

<Steps>

<Step>
### Link a repo

Start a new project, or link an existing repo folder to one.

To scaffold a new project:

```sh
zed init my-app
cd my-app
```

`zed init` creates a project directory with the general-purpose starter. Its
`zed.yaml` declares `zed_version: 2` and runs OpenCode.

To link an existing cloned repo to a project you already created:

```sh
zed projects link <project-id>
```

This command writes `.zed/link.json` in the current directory. Zed reads this file to find your project on every command run from this folder. If you plan to run `zed ship` first, skip this step. It links a new project for you when none exists.
</Step>

<Step>
### Ship your code

```sh
zed ship
```

`zed ship` lints your `zed.yaml`, commits local changes, pushes your branch, and prompts for any missing secret or connection. Run it each time you want your local changes on the cloud project. The first run also creates the cloud project and repo if you have not linked one yet.
</Step>

<Step>
### Run and attach to sessions

Start a session with a prompt:

```sh
zed sessions new --prompt "Build the login page" --wait
```

Each session runs in its own sandbox, on its own branch. `--wait` blocks until the session is ready.

Attach to a session from your terminal:

```sh
zed sessions chat
```

This opens an interactive chat with your most recent session. Add an id to target a specific session: `zed sessions chat <id>`.

To attach your local OpenCode client to the sandbox instead, run:

```sh
zed sessions connect
```

This command attaches to the OpenCode REST process.

To open a raw shell in the sandbox, with no agent involved, run:

```sh
zed sessions shell
```

List your running sessions at any time:

```sh
zed sessions ls
```
</Step>

<Step>
### Review with change requests

An agent opens a change request (CR) when its session has commits ready to merge. List, inspect, and merge them from the CLI.

```sh
zed cr ls
zed cr diff 1
zed cr merge 1
```

`zed cr ls` lists change requests for the linked project. `zed cr diff <cr>` shows the unified patch. `zed cr merge <cr>` merges it into the project's default branch. Accept a CR number or its full id.
</Step>

</Steps>

## Reference

### Auth commands

| Command | Effect |
| --- | --- |
| `zed login [--host <name>] [--api <url>] [--token <pat>] [--account <slug>] [--no-project]` | Sign in to the active host, or the named one. Opens a browser by default; `--token` signs in headless. `--no-project` skips the default-project pick. |
| `zed logout [--host <name>]` | Remove the token for the active host, or the named one. |
| `zed whoami [--host <name>] [--json] [--token-only]` | Print the signed-in user and active account. |
| `zed token [--host <name>]` | Shortcut for `zed whoami --token-only`. |

`zed hosts login` / `hosts logout` / `hosts whoami` are the canonical forms. `login` / `logout` / `whoami` are shortcuts that act on the active host.

### Hosts

| Command | Effect |
| --- | --- |
| `zed hosts ls [--json]` | List every host and its auth status. |
| `zed hosts login [<name>] [--token <pat>] [--api <url>] [--account <slug>] [--no-project]` | Sign in to a host. An unknown name registers the host first. |
| `zed hosts logout [<name>]` | Remove the token for a host. |
| `zed hosts use <name>` | Switch the active host. |
| `zed hosts add <name> --url <url> [--dashboard-url <url>] [--login]` | Register a new host. `--login` signs in right after. |
| `zed hosts rm <name> [--force]` | Remove a host. |
| `zed hosts info [<name>] [--json]` | Show details for one host. |
| `zed hosts current [--json]` | Print the active host name. |

A remote host URL that starts with `http://` is normalized to `https://`. The CLI never sends a token over plain HTTP to a remote host. `localhost` is exempt.

### Accounts

| Command | Effect |
| --- | --- |
| `zed accounts ls [--json]` | List the accounts you belong to on the active host. |
| `zed accounts use [<slug-or-id>]` | Switch the active account. |
| `zed accounts current [--json]` | Print the active account. |
| `zed accounts info [<slug-or-id>] [--json]` | Show one account. |

### Projects

A command resolves "the project" in this order:

1. The `--project` flag.
2. The `ZED_PROJECT_ID` environment variable.
3. `.zed/link.json` in the exact working directory.
4. The global default set by `zed projects use`.

| Command | Effect |
| --- | --- |
| `zed projects ls [--all] [--json]` | List projects on the active account. `--all` spans every account you belong to. |
| `zed projects info [<id>] [--json]` | Show one project. Default: the linked or default project. |
| `zed projects use [<id>]` | Set the global default project. Switches the active account if the project lives elsewhere. |
| `zed projects unset` | Clear the global default project. |
| `zed projects link [<id>]` | Bind the current directory to a project. Writes `.zed/link.json`. |
| `zed projects unlink` | Remove `.zed/link.json`. |
| `zed projects open [<id>]` | Open a project's dashboard page in your browser. |
| `zed projects clone [<id>] [dir]` | Clone a project's repo through the authenticated Zed git proxy. |
| `zed projects rm [<id>] [--purge] [-y\|--yes]` | Archive a project. `--purge` also deletes its managed git repo. |

### Project scaffold

`zed init [project-name] [options]` creates a new project directory. The
starter writes a v2 `zed.yaml` and the canonical `.zed/opencode`
system-skill source. The command can wire local coding-tool discovery without
changing the cloud OpenCode runtime. The command does not write
`.zed/link.json`. `zed ship` or `zed projects link` create that file.

| Flag | Meaning |
| --- | --- |
| `--name <project>` | Project name. |
| `--primary <agent>` | Primary agent. |
| `--agents <csv>` | Local coding-agent integrations to wire up. |
| `--force` | Configure the current directory in place instead of scaffolding a new one. |
| `--overwrite` | Overwrite existing files. |
| `--no-git` | Skip git init. |
| `-y, --yes` | Don't prompt. |

The local coding-tool selection does not change the cloud OpenCode runtime.

`zed init` does not include a marketplace picker. Adding a marketplace skill is an agent import: start a session and ask the agent to bring one in.

### Ship

`zed ship` stages, commits, and pushes your current branch to the project's git repo. Run it once to create the project. Run it again any time to sync. Alias: `zed deploy`.

Each run:
- Parses and validates `zed.yaml` (skip with `--no-verify`).
- Commits any dirty working tree (skip with `--no-commit`).
- Prompts for any missing `env` secret (skip with `--no-env`).
- Pushes the current branch to the same-named remote branch.
- Connects any declared connector that still needs auth (skip with `--no-connect`).

An existing GitHub `origin` links through the Zed GitHub App. Any other existing `origin` is registered as-is. No `origin` creates a managed Zed git repo.

| Option | Effect |
| --- | --- |
| `--name <project>` | Display name for a new project. |
| `--account <id\|slug>` | Account to create the project under (first ship only). |
| `--origin <managed\|git-url>` | Override the inferred origin choice. |
| `--github-token <pat>` | Link a GitHub origin with this token instead of the GitHub App. |
| `-m, --message <text>` | Commit message. |
| `--no-commit` / `--no-verify` / `--no-env` / `--no-connect` | Skip that step. |
| `-y, --yes` | Don't prompt. |
| `-n, --dry-run` | Print what would happen; change nothing. |
| `--project <id>` / `--host <name>` | Target a non-default project or host. |

### Sessions

Each session runs in one sandbox on its own branch.

| Command | Effect |
| --- | --- |
| `zed sessions ls` | List every session on the project. |
| `zed sessions status [--all] [--json]` | Every session and what its agent is doing right now. Aliases: `overview`, `ps`. |
| `zed sessions info <id> [--json]` | Detail view: status, branch, agent, sandbox URL. |
| `zed sessions new [--prompt "<text>"] [--agent <name>] [--model <id>] [--wait] [--json]` | Start a session. `--model <id>` overrides the project's default model. `--wait` blocks until it is running (up to ~5 minutes). Use `--secret <id>` or `--no-secrets` to narrow Secret access. These Secret flags require a backend token. Use `--connector <alias>=<authorization-id>` or `--no-connectors` to set Connector access. Use `--require-connector <alias>` to require an authorization before provisioning. Scope flags are repeatable. Use `--context <key>=<value>` for non-secret runtime context. |
| `zed sessions chat [<id>] [--prompt "<text>"] [--new] [--agent <name>] [--json]` | Talk to a session's agent. Interactive by default. Alias: `talk`. Top-level `zed chat` also works. |
| `zed sessions connect [<id>] [-- <opencode args>]` | Attach your local OpenCode TUI to the OpenCode REST compatibility process in the sandbox. Alias: `attach`. |
| `zed sessions shell [<id>] [--new]` | Open a raw interactive terminal in the sandbox, with no agent. Aliases: `terminal`, `ssh`. |
| `zed sessions log [<id>] [--limit <n>] [--json]` | Print recent messages, read-only. Aliases: `messages`, `history`. |
| `zed sessions pending <id> [--json]` | List open tool-permission or question prompts. Alias: `prompts`. |
| `zed sessions approve <id> [<req-id>] [--always] [--reject] [--message "<text>"]` | Answer a permission prompt. |
| `zed sessions answer <id> [<req-id>] [--option <v>]... [--text "<text>"] [--reject]` | Answer a question prompt. |
| `zed sessions digest [--since <7d>] [--json]` | Compact multi-session review. Aliases: `review`, `summary`. |
| `zed sessions scope <id> [scope options] [--json]` | Read or replace Secret and Connector access. Alias: `access`. Use `--secret <id>`, `--no-secrets`, or `--inherit-secrets` for Secrets. Use `--connector <alias>=<authorization-id>` or `--no-connectors` for Connector bindings. Use `--require-connector <alias>` or `--no-required-connectors` for required Connectors. Provided categories replace their current values. Omitted categories remain unchanged. Changes apply to the next prompt. Removed Secret values remain in existing context if the session already read them. |
| `zed sessions preview <id> [port] [--port <n>] [--json]` | Print a clickable preview URL for a sandbox port. Default port: `3000`. |
| `zed sessions restart <id>` | Restart the session's sandbox. |
| `zed sessions rename <id> <name>` | Set a session's name. Pass `""` to clear it. |
| `zed sessions rm <id>` | Stop and delete a session. |
| `zed sessions open <id>` | Open a session's dashboard page in your browser. |

Inside a sandbox, `ZED_SESSION_ID` is your own session's id.

### Change requests

A change request (CR) merges one branch into another on any git host. It is the only way for an agent to land session work on the default branch. See [Change requests](/docs/work/change-requests).

| Command | Effect |
| --- | --- |
| `zed cr ls [--status open\|merged\|closed\|all] [--project <id>]` | List CRs. Default: `--status open`. |
| `zed cr show <cr> [--project <id>]` | Show one CR, including its merge preview. Alias: `info`. |
| `zed cr diff <cr> [--no-color] [--json]` | Print a CR's unified diff. |
| `zed cr open --title "<text>" [--description "<text>"] [--head <ref>] [--session <id>] [--base <ref>]` | Open a CR. Aliases: `new`, `create`. Inside a sandbox, `--head` and `--session` default automatically. `--base` defaults to the project's default branch. |
| `zed cr merge <cr> [--message "<text>"]` | Merge an open CR. Fast-forward when possible, three-way merge otherwise. |
| `zed cr close <cr>` | Close an open CR without merging. |
| `zed cr reopen <cr>` | Reopen a closed CR. Merged CRs are terminal. |

`<cr>` accepts a per-project number (`3`) or the full id. Inside a sandbox, the CLI reads its token automatically — no login or link needed.

### Secrets

Encrypted values stored on the project and injected as plain environment variables into every session sandbox at boot.

| Command | Effect |
| --- | --- |
| `zed secrets ls` | List secrets by identifier and manifest `env` spec. Marks required-but-missing values. |
| `zed secrets set NAME=VALUE ... [--identifier <id>]` | Upsert one or more secrets. `NAME=-` reads the value from stdin. |
| `zed secrets request NAME ... [--scope runtime\|connector] [--expires <min>]` | Mint a link for a human to enter a value directly — you never see the raw value. |
| `zed secrets unset NAME ...` | Remove secrets. |

### Env

| Command | Effect |
| --- | --- |
| `zed env pull [--out <path>] [--force]` | Write a `.env` skeleton — names only. Values never leave the cloud. |
| `zed env push --from <path>` | Upload every `NAME=VALUE` from a dotenv file as a secret. |

### Agents

Per-agent model settings on the linked project.

| Command | Effect |
| --- | --- |
| `zed agents models [--json]` | Show every agent's pinned model and the fallback default. |
| `zed agents model <agent> <provider/model>` | Pin an agent to a model. |

### Channels

Manages the project's connection to a chat platform. Tokens are stored encrypted in the project's secrets and resolved server-side — they are never injected into the sandbox.

| Command | Effect |
| --- | --- |
| `zed channels status [--json]` | Show the current connection. |
| `zed channels connect [--wait] [--timeout <sec>]` | Connect in one step: prints an install link. `--wait` polls until the install lands. |
| `zed channels connect --manual [--bot-token <token>] [--signing-secret <secret>]` | Bring-your-own-app mode: save a bot token and signing secret directly. |
| `zed channels disconnect` | Remove the project's channel secrets. |
| `zed channels manifest` | Print the app manifest JSON for the bring-your-own-app path. |

`--platform slack|teams` selects the platform; default `slack`. See [Connectors](/docs/connect/connectors).

### Connectors

Connectors an agent calls as tools. `add`, `rm`, and `policy set` edit the local `zed.yaml`; run `zed ship` to apply, unless you pass `--apply` to change the cloud project immediately.

| Command | Effect |
| --- | --- |
| `zed connectors ls [--json]` | List connectors and their status. |
| `zed connectors show <slug> [--json]` | Show one connector's tools. |
| `zed connectors add <slug> --provider <p> [options] [--apply]` | Add a connector. |
| `zed connectors rm <slug> [--apply]` | Remove a connector. |
| `zed connectors rename <slug> <name>` | Set a connector's display name. |
| `zed connectors sync` | Reconcile the catalog from the shipped `zed.yaml`. |
| `zed connectors credential <slug> [value]` | Set a connector's credential. |
| `zed connectors connect <slug>` | Start a one-click connect flow. |
| `zed connectors link <slug> [--expires <min>]` | Mint a shareable connect link for a human. |
| `zed connectors apps [<query>] [--json]` | Browse the connector app catalog. |
| `zed connectors policy ls [--json]` | Show project-wide execution policy. |
| `zed connectors policy set --default <risk\|allow_all>` | Set the default execution mode. |
| `zed connectors policy <slug> ls\|set <match> <allow\|ask\|block>\|rm <match>\|clear` | Manage one connector's tool-call rules. |

`add` options: `--name <label>`, `--provider <pipedream\|mcp\|openapi\|postman\|graphql\|http>`, `--app <slug>`, `--url <url>`, `--transport <http\|sse>`, `--endpoint <url>`, `--base-url <url>`, `--spec <url\|path>`, `--auth-type <none\|bearer\|basic\|custom>`, `--credential shared`.

### Sandboxes

Manages the project's sandbox images. A template defines an image or Dockerfile plus resources; a build produces the snapshot sessions boot from.

| Command | Effect |
| --- | --- |
| `zed sandboxes ls [--json]` | List templates and live provider state. |
| `zed sandboxes builds [--json]` | Recent build log. |
| `zed sandboxes health [--json]` | Primary template readiness. |
| `zed sandboxes add <slug> (--image <i>\|--dockerfile <p>) [options]` | Create a custom template and start a build. |
| `zed sandboxes update <slug> [options]` | Update a template. |
| `zed sandboxes build <slug>` | Trigger a rebuild. |
| `zed sandboxes rebuild <slug>` | Force-rebuild: delete the existing snapshot first. |
| `zed sandboxes rm <slug>` | Delete a template. |
| `zed sandboxes fix` | Start a session seeded with the last failed build log, to repair it. |

`add`/`update` options: `--name <label>`, `--cpu <n>`, `--memory <n>` (GiB), `--disk <n>` (GiB).

### Marketplace

Read-only discovery of marketplace items. Installing an item into a project is an agent import, done from inside a session — there is no install command.

| Command | Effect |
| --- | --- |
| `zed marketplace search [query]` | Search marketplace items. |
| `zed marketplace list` | List marketplace items. |
| `zed marketplace show <id-or-name>` | Show one marketplace item. |

Options: `--query <text>`, `--type <type>`, `--source <source>`, `--host <name>`, `--json`.

### System skills

The Zed system skills are the platform's own documentation. They cover
sessions, sandboxes, OpenCode, the connector, memory, and
channels. The API serves them live, so they match the deployed host version.
The binary and a token are enough for an agent to retrieve this context.

| Command | Effect |
| --- | --- |
| `zed system-skills list` | List the Zed system skills. Default subcommand. |
| `zed system-skills get <name> [--full]` | Print one skill's current `SKILL.md`. `--full` adds its referenced files. |
| `zed system-skills path [name]` | Print a skill's on-disk directory in this project. |

Options: `--host <name>`, `--json`.

`zed skills` is a permanent alias for the same command.

This list is always the system skills, never a mix. Optional skills live in the marketplace: `zed marketplace list --type skill`.

### Connector

The in-sandbox agent's interface to every connector. Every call is checked, resolved, and audited server-side; the CLI never holds a third-party credential. Auth: `ZED_CLI_TOKEN`. Output is JSON.

| Command | Effect |
| --- | --- |
| `zed connectors discover "<intent>"` | Search tools by natural-language intent. |
| `zed connectors show <connector>.<action>` | Show an action's input schema. |
| `zed connectors call <connector>.<action> '<json-args>'` | Run a tool. A governed call returns its authenticated `approval_url` immediately. The server resumes the session after one approve or deny decision. |
| `zed connectors add <slug> --provider pipedream --app <app>` | Add a connector immediately, then connect it. |
| `zed connectors rm <slug>` | Remove a connector from the project. |
| `zed connectors connect <slug>` | Mint a connect link for a human. |
| `zed connectors mcp` | Run the optional stdio MCP compatibility server. |

### Triggers

A trigger starts a session from a schedule or a webhook. `add`, `rm`, `enable`, `disable` edit the local manifest — run `zed ship` to apply. `pause`/`resume` flip a separate, server-side switch. See [Triggers](/docs/connect/triggers).

| Command | Effect |
| --- | --- |
| `zed triggers ls [--json]` | List triggers and their runtime state. |
| `zed triggers add <slug> [options]` | Append a trigger to the manifest. |
| `zed triggers rm <slug>` | Remove a trigger. |
| `zed triggers info <slug> [--json]` | Show one trigger. |
| `zed triggers fire <slug>` | Fire a trigger manually. |
| `zed triggers enable <slug>` / `disable <slug>` | Turn one trigger on or off. |
| `zed triggers pause` / `resume` | Deactivate or reactivate every trigger on the project, server-side. |

`add` options: `--type <cron\|webhook>` (default `cron`), `--prompt <text>` (required), `--agent <name>`, `--cron <expr>`, `--timezone <tz>` (default UTC), `--secret-env <NAME>`, `--name <label>`, `--disabled`.

### Audit

The audit commands read the centralized reconstruction log. Account and project
lists are newest first. A session timeline is ordered by its monotonic
`session_sequence`. `--all` follows every continuation cursor.

| Command | Effect |
| --- | --- |
| `zed audit ls [filters] [--all] [--json]` | List account events. |
| `zed audit project <project-id> [filters] [--all] [--json]` | List one project's events. |
| `zed audit session <session-id> --project <project-id> [--all] [--json]` | Reconstruct one session in order. |
| `zed audit export [filters] --format csv\|jsonl --out <file>` | Resume every export page into one file. |

Filters: `--actor`, `--actor-type`, `--project`, `--session`, `--source`,
`--phase`, `--outcome`, `--action`, `--resource-type`, `--request-id`,
`--correlation-id`, `--query`, `--since`, `--until`, `--cursor`, and `--limit`.
Account lists and exports require `audit.read` and the account's `auditAccess`
entitlement. Project-wide lists require `project.members.manage` because they can
include private-session metadata. Session reconstruction requires
`project.session.read` and visibility of that session.

### Self-host

`zed self-host` runs one Docker-based stack, identical on a laptop, a VPS, or a cloud VM. See [Self-hosting](/docs/host) and [Self-hosting architecture](/docs/host/architecture).

| Command | Effect |
| --- | --- |
| `zed self-host init` | Create or refresh the self-host config. Does not start the stack. |
| `zed self-host configure` | Interactive wizard for connections and update policy. |
| `zed self-host doctor` | Validate Docker tooling and the rendered config. |
| `zed self-host plan` | Validate the rendered Compose config; change nothing. |
| `zed self-host start` | Create config if needed, then start the stack. Aliases: `up`, `deploy`. |
| `zed self-host update [--tag <v>\|--channel stable\|latest]` | Pull images for the configured channel or tag and recreate the stack. Alias: `upgrade`/`reconcile`. |
| `zed self-host rollback --release <v>` | Roll back to an explicit older version. |
| `zed self-host version` | Show the running version and channel. |
| `zed self-host restart` / `stop` | Restart or stop the stack. Alias for stop: `down`. |
| `zed self-host status` / `ps` | Show service status. |
| `zed self-host open` | Open the dashboard in your browser. |
| `zed self-host connect-github` | Connect a GitHub App for managed repos. |
| `zed self-host env ls [--show]` | Show persistent config values, masking secrets by default. |
| `zed self-host env set KEY=VALUE ...` | Set a value and restart only the services it affects. |
| `zed self-host env rotate KEY\|--all-generated` | Regenerate a rotatable, CLI-generated secret. |
| `zed self-host logs [service]` | Tail stack logs. |
| `zed self-host uninstall` | Stop the stack and delete this instance's containers, volumes, and config. |

Common flags: `--instance <name>` (default `default`), `--domain <domain>`, `--tunnel cloudflare`, `--version`/`--tag`/`--release <v>`, `--channel stable|latest` (default `stable`), `--auto-update on|off` (default `on`; forced off by `--local-images`), `--update-time <HH:MM>` / `--update-tz <tz>` (auto-updater schedule), `--local-images` (run locally-built images; dev mode), `--enterprise-license` (unlock SSO/SCIM/RBAC/audit), `--admin-email <email>`, `--no-restrict-account-creation` (let any signed-in user create new accounts/orgs; default is admin-only), `--restrict-account-creation` (re-enable the admin-only default), `--json`, `--yes`.

### Token scope

Every token starts with `zed_pat_`. A user token is scoped to every project on your accounts. A project token is scoped to one project and auto-injected into that project's sandboxes. See the full token-family reference at [Session runtime](/docs/work/runtime).
